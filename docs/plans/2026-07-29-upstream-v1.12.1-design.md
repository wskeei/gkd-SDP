# GKD v1.12.1 上游合并设计

## 目标

将原项目 `gkd-kit/gkd` 的正式版本 `v1.12.1` 合并到 GKD-SDP，同时保留当前项目已有的 Focus Mode、App Blocker、URL Blocker、Usage Guard、自动恢复、锁定策略、数据兼容性、独立应用 ID 与发布流程。

## 已知边界

- 当前 SDP 分支与上游共同祖先为 `dcae91970f07dc6c97a0d09f8fdb9bc4570b1718`。
- SDP 相对共同祖先有 127 个提交；上游 `v1.12.1` 有 98 个提交。
- 上游仍使用 `li.songe.gkd`，SDP 已整体迁移到 `li.songe.gkd.sdp`。
- 三方合并预演表明 Git 能识别目录迁移，但核心运行时、Shizuku、UI、构建配置存在大量语义冲突。
- 本机当前没有 Java 与 Android SDK；Android 编译以 GitHub Actions 为最终证据，本地仍执行静态审计和环境允许的测试。

## 合并策略

在项目内的 `.worktrees/upstream-v1.12.1` 隔离工作树和 `merge/upstream-v1.12.1` 分支上执行真实的三方合并，以保留上游祖先关系，便于未来继续同步。冲突不采用全局 `ours` 或 `theirs`，而是按模块处理：

1. 自动合并无冲突文件，并检查是否意外残留 `li.songe.gkd` 旧命名空间。
2. 构建、依赖和 Manifest 以 SDP 身份与 flavor 为约束，吸收上游工具链和 Android 兼容更新。
3. selector、订阅、快照和日志等上游核心能力优先采用上游行为，再恢复 SDP 的扩展调用。
4. 无障碍与 Shizuku 以 `v1.12.1` 的修复为基础，逐处重新接入 Focus/App/URL/Usage Guard。
5. UI 以 SDP 导航和页面为骨架，移植上游的新页面、状态组件和缺陷修复。
6. 数据库和设置必须保持向后兼容；不删除 SDP 表、迁移、字段或持久化键。

## 风险控制

- 每完成一个独立模块就提交一次，确保能够定位和回退。
- 对所有冲突文件检查冲突标记、旧包名、重复类、Manifest 组件和资源引用。
- 对上游删除但 SDP 修改的文件逐一确认，禁止机械删除。
- 对更新检查逻辑保留 SDP 的应用身份与发布地址，避免继续收到原版 GKD 更新通知。
- 使用现有 policy/unit tests 覆盖定制功能；必要时补充静态契约测试，防止合并后入口或调用链丢失。

## 验收

- 工作树无未解决冲突，无冲突标记或错误包名。
- SDP 定制功能的实现、入口、持久化与运行时挂接仍存在。
- `:selector:jvmTest`、`:app:testGkdDebugUnitTest` 和 Actions 中的 APK 构建通过。
- GKD 与 Play 两个 flavor 的 GitHub Actions 构建通过。
- 合并历史明确记录 `upstream-v1.12.1`，后续可以从该版本继续增量同步。
